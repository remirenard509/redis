01 · Qu’est-ce que Redis ?Redis — Question 4

Une base de données clé-valeur qui vit en mémoire vive

Redis (REmote DIctionary Server) range chaque donnée sous une clé unique et garde tout en RAM. Créé en 2009 par Salvatore Sanfilippo, c’est l’une des bases NoSQL les plus répandues.

  • En mémoireLes lectures ne touchent pas le disque : une commande s’exécute en quelques microsecondes côté serveur.
  • TypéeUne valeur peut être une chaîne, un hash, une liste, un ensemble trié, un stream… ou un document JSON avec Redis Stack.
  • Persistante
    si on le veut    Snapshots périodiques (RDB) et/ou journal des écritures (AOF) sur disque.
  • DistribuableRéplication, bascule automatique (Sentinel), partitionnement (Cluster).

Redis — Question 402 / 09
02 · Pourquoi l’utilise-t-on ?Redis — Question 4

Parce qu’il est rapide, simple, et fait plus qu’un cache

01

Vitesse

Tout est en RAM : 3,8 µs de travail par lecture côté serveur. L’écart le plus net est en écriture : une mise à jour ×5 plus rapide que PostgreSQL (1 client).

JSON.GET obscop2025:row:1
02

Calcul côté serveur

Redis sait incrémenter, trier, empiler. Ces commandes sont atomiques : pas de « lire, modifier, réécrire » dans l’application.

ZINCRBY classement 10 alice
03

Expiration intégrée

Chaque clé peut avoir une durée de vie (TTL). Idéal pour un cache, une session ou un code à usage unique.

SET otp:42 "839201" EX 300
04

Simple à adopter

Protocole texte, clients dans tous les langages (redis-py ici), démarrage en une commande Docker.

docker run -p 6379:6379 …
Les limites

Les données doivent tenir en RAM · un seul cœur exécute les commandes · pas de SQL ni de jointures · la durabilité dépend de la persistance configurée. Redis vient donc le plus souvent en complément d’une base principale, pas à sa place.

03 · ExemplesRedis — Question 4

Six usages classiques, deux commandes chacun

Cache STRING + TTL

Garder 60 s le résultat d’une requête SQL ou d’une API lente.

SET cache:produits:42 "{…}" EX 60
GET cache:produits:42

Sessions HASH

Session web partagée par plusieurs serveurs, supprimée après 30 min.

HSET session:8f3a user_id 42 panier 3
EXPIRE session:8f3a 1800

Limitation de débit INCR

Au plus 100 requêtes par minute et par adresse IP.

INCR rl:203.0.113.7    # → 1, 2, 3…
EXPIRE rl:203.0.113.7 60

Classement SORTED SET

Scores d’un jeu, articles les plus lus, mis à jour en temps réel.

ZINCRBY classement 10 alice
ZREVRANGE classement 0 9 WITHSCORES

File de tâches LIST

Envoi d’e-mails en arrière-plan. Sidekiq, BullMQ ou Celery peuvent s’appuyer sur Redis.

LPUSH jobs:emails "{to: …}"
BRPOP jobs:emails 0   # bloque, attend

Temps réel PUB/SUB

Chat, notifications : les abonnés reçoivent chaque message instantanément.

SUBSCRIBE chat:general
PUBLISH chat:general "Bonjour"

En résumé

01 · Qu’est-ce que c’est ?

Une base clé-valeur en mémoire

Des valeurs typées (chaînes, hashes, listes, ensembles triés, streams, JSON), des commandes atomiques, une persistance optionnelle sur disque.

Commandes vuesSET · GET · HSET · ZADD · JSON.SET
02 · Pourquoi ?

Pas pour lire plus vite qu’une base indexée

Sur des données en mémoire, PostgreSQL fait jeu égal. Redis sert à éviter de recalculer, à absorber des écritures légères (sessions, compteurs) et à profiter du TTL et de ses structures.

Mesurécache ×78 · mise à jour ×5 (1 client)

Cache, sessions, files, temps réel

Chez nous : le tableau de bord A1BIS servi en 0,23 ms au lieu de 18,2 ms, et 146 275 lignes tenues dans 141 Mo de RAM.
